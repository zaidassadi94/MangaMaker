# Decisions

Reasonable choices made while building MangaForge, and the trade-offs behind
them.

## Mock-first architecture

The **mock image provider** and the **mock story generator** were built first
and are the default. Every screen and the entire generation pipeline work with
zero API keys, deterministically. This is what makes CI green on a clean clone
with no secrets, and what makes the app demoable offline.

- The mock provider returns a URL to `/api/mock-image`, which renders a
  deterministic SVG placeholder from query params. This means **no base64 in the
  DB** and **no filesystem writes**, so the mock path also works on read-only
  serverless hosts.
- Committed seed art in `/public/seed` inlines the placeholder SVG as data URIs
  so those files are self-contained (openable without the server running) and
  their provenance is unambiguous.

## Data model: embedded JSON for bubbles & SFX

The spec lists `Bubble` and `Sfx` as separate entities. They are stored as JSON
columns on the `panels` row instead of separate tables. Rationale: the editor
autosaves and undoes whole-page snapshots, so a single serialisable panel record
(with its bubbles and SFX) keeps autosave and undo/redo to one code path and
avoids fan-out joins. `StyleGuide` is likewise embedded on `projects`. IDs are
still generated per bubble/SFX so the objects remain individually addressable.

## Database: libSQL driver

Drizzle's libSQL driver is used so `DATABASE_URL` accepts both a local file
(`file:./data/mangaforge.db`, the dev default) and a remote Turso `libsql://`
URL with **no code changes**. Schema is created idempotently at runtime via
`CREATE TABLE IF NOT EXISTS` (`src/lib/db/ensure.ts`) so a fresh clone needs no
migration step; `drizzle-kit` is still wired up (`pnpm db:generate`) for those
who want versioned migrations.

## Storage adapter

`local` (writes to `/public/generated`) is the dev default; `s3` targets any
S3-compatible endpoint (R2, B2, MinIO) via `aws4fetch` (SigV4 over `fetch`, no
heavyweight SDK). Generated bytes are always referenced by URL in the DB, never
base64 — so the app is deployable to hosts with a read-only/ephemeral filesystem
(deploy with `STORAGE_ADAPTER=s3`).

## Claude model id

The story pipeline defaults to the model in the spec (`claude-sonnet-4-6`) but
it is overridable via `ANTHROPIC_MODEL`. If a call fails or the key is unset, it
falls back to the deterministic mock story generator, so the pipeline always
returns valid, schema-checked data.

## Export: client raster + server vector

- The **client exporter** rasterises the shared SVG page composition
  (`src/lib/compose-svg.ts`) to canvas and produces PNG (zip), PDF (jsPDF),
  CBZ (jszip + ComicInfo.xml), and a stitched webtoon JPEG. This is the primary
  path and satisfies "valid PDF, CBZ, PNG set."
- The **server route** `POST /api/export/:projectId` returns a ZIP of the same
  pages as vector SVGs (infinite resolution, provenance-clean) plus a manifest.
  Server-side rasterisation was avoided to keep zero native dependencies (no
  `sharp`/`resvg` build step), which keeps CI and forks friction-free.

## Bubble rendering duplicated (Konva + SVG)

Bubbles are drawn twice: as interactive Konva vector shapes in the editor, and
as SVG in the shared composer used by thumbnails, the reader, and export. This
is deliberate duplication — the editor needs Konva interactivity, while
thumbnails/reader/export need a pure, DOM-free string. The geometry is simple
enough that a shared abstraction wasn't worth the indirection.

## MIT vs AGPL

Licensed **MIT** for maximum reuse. If you later want to discourage closed
hosted clones, swapping `LICENSE` for **AGPL-3.0** is the single change — it
requires network-served modifications to publish source. Trade-off: AGPL narrows
adoption (many companies avoid it) in exchange for reciprocity. MIT was chosen to
favour a healthy contributor ecosystem.

## Rate limiting & quota

Per-IP sliding-window rate limiting is in-memory by default and uses Upstash
Redis REST when configured. A separate server-enforced **daily panel cap**
(`MAX_PANELS_PER_DAY`, tracked in a `usage` table keyed by day + hashed IP)
blocks floods independently of the rate window, and remaining quota is surfaced
in the UI after each generation. Chapter length is hard-capped
(`MAX_PAGES_PER_CHAPTER`).

## Known simplifications

- **Inpaint** provides a real paint-a-mask modal; the mask is passed to the edit
  endpoint (used by Gemini/fal). The mock provider ignores the mask and returns a
  deterministic variant.
- **Multi-select / align / distribute** in the canvas is not implemented; single
  selection with drag/resize/rotate is. Everything else in §7/§8 (snapping,
  zoom/pan, safe-margin overlay, reading-order overlay, inline text edit, tail
  dragging) is present.
- Style-guide sliders (line weight / tone density / ink contrast) adjust
  in-session prompt flavour but are not persisted back to the project row.
